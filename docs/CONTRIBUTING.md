# 開発のすすめかた

## 最初に

```bash
pnpm install
pnpm dev
```

エディタは VS Code を想定しています。推奨拡張は `.vscode/extensions.json` に。

## push する前に

```bash
pnpm check
```

型・lint・マスタ検査・テストを全部通します。これが赤いまま push しないでください。
CI でも同じものが走ります。

## ブランチとコミット

- `main` は常に遊べる状態を保つ。直接 push しない
- 作業は `feat/○○` `fix/○○` `balance/○○` から切る
- コミットメッセージは日本語で、**何をしたか**を一行目に

```
進化の硬直中に石高が溜まらない不具合を直す

硬直の判定が evolving だけを見ていて、evoT が残っている
あいだの回復を止められていなかった。
```

## どこを触るか

| やりたいこと                       | 触る場所                                                             |
| ---------------------------------- | -------------------------------------------------------------------- |
| 数値の調整（HP・コスト・敵の湧き） | `src/data/master.json` **だけ**。コードは触らない                    |
| 新しい系譜（ユニット）を足す       | `master.json` の `lineages` に追加 → 見た目が要れば `render/unit.ts` |
| 新しい時代を足す                   | `master.json` の `eras` `music` `balance` の各配列すべてに 1 つずつ  |
| 戦闘の挙動を変える                 | `src/sim/`。**変えたら `pnpm test` が赤くなるはず**（下記）          |
| 画面・HUD                          | `src/ui/`                                                            |
| 絵                                 | `src/render/`                                                        |
| 音                                 | `src/audio/index.ts`                                                 |

### マスタデータを触るとき

`master.json` は運営が触る前提のファイルです。編集したら必ず：

```bash
pnpm validate:master
```

時代を1つ増やすなら、**時代数ぶんの配列すべて**を伸ばす必要があります
（`statMul` `costMul` `kokuMax` `kokuRegen` `fumiNeed`、各系譜の `forms`、
各ステージの `reward.mat`、`music`）。検査がこれを見張ります。

Prettier は `master.json` を整形しません。人が縦に読む並びを壊さないためです。

### 絵を差し替えるとき

絵は二段になっています。

| 置き場        | 中身                     | Git                                            |
| ------------- | ------------------------ | ---------------------------------------------- |
| `asset/`      | 原寸の素材（1枚 1〜3MB） | **追跡しない**（247MB あり、履歴が膨らむため） |
| `src/assets/` | 実行用に縮めたもの       | 追跡する。ゲームが読むのはこちら               |

書き出しは PowerShell の script が行います。

```powershell
pwsh scripts/prepare-visual-assets.ps1     # 背景・拠点・前景・飛び道具ほか
pwsh scripts/prepare-unit-assets.ps1       # 兵・主・妖
```

> **`asset/` は各自の手元にしかありません。** clone しただけでは付いてきません。
> ゲームのビルドには `src/assets/` があれば足りるので困りませんが、
> **絵を描き直すには原寸が要ります。** 素材を持っている人から受け取るか、
> 共有の置き場（外付け・クラウド）から取ってください。
> 消すと描き直せなくなるので、控えを別の場所に取っておくこと。

### シムを触るとき

`tests/determinism.test.ts` の「同じ種・同じ入力なら盤面が1ビットも違わない」は
**絶対に落としてはいけません**。ここが落ちるときは、実時間や `Math.random()` が
シムに混ざっています。

一方、盤面の中身が変われば結果が変わるのは当たり前です。
バランス調整で他のテストが落ちたら、それは想定内 ── 期待値のほうを直してください。

`sim/` から `ui/` を import しようとすると lint が止めます。
決着の通知は `sim/outcome.ts` の `finishGame()` を使ってください。

### 乱数

| 用途                               | 使うもの             |
| ---------------------------------- | -------------------- |
| 盤面に効く（敵の編成・湧きの間隔） | `G.rng()`            |
| 演出だけ（破片の飛び方）           | `vrng()`             |
| シムの外（音のゆらぎ・召集）       | `Math.random()` で可 |

`sim/` の中で `Math.random()` を書くと lint が止めます。

## 保存データを壊さない

`SAVE_V`（`core/constants.ts`）を上げると、**全ユーザーの進行が消えます**。
形を変えるときは、`loadSave()` に古い形からの読み替えを足してください
（`LINE_OLD` が、三系統だったころの技レベルを読み替えている実例です）。

`REC_V` を上げると、保存済みのゴーストが捨てられます。
入力ログの意味を変えたときだけ上げてください。

## テストの置き場

| ファイル                    | 見張っているもの                                   |
| --------------------------- | -------------------------------------------------- |
| `tests/determinism.test.ts` | 再現性。ゴーストとリプレイの土台                   |
| `tests/master.test.ts`      | マスタの参照が壊れていないか                       |
| `tests/boot.test.ts`        | 起動できるか。`$("id")` が index.html に実在するか |
| `tests/rng.test.ts`         | 乱数の並びが変わっていないか                       |

`boot.test.ts` は Canvas2D を殻で受け流します。**絵の正しさは見ていません**。
見た目の確認は `pnpm dev` で目視してください。
