# 構成

## この設計が守っているもの

**一戦の結果は、シードと入力ログだけで完全に再現できる。**

これが崩れると、ゴースト（自己ベストの並走）もリプレイも、
将来のサーバー側チート検証も、まとめて成り立たなくなります。
以下の決まりは、すべてこの一点を守るためにあります。

- 盤面に効く乱数は `G.rng()` からしか引かない。演出の揺らぎは `vrng()`
- シムは実時間を見ない。`DT = 1/60` の固定タイムステップだけで進む
- シムは DOM を知らない。画面の有無で結果が変わってはいけない
- 画面寸法（`SC` / `GY` / `OX`）はシムに入らない。ウィンドウの大きさで勝敗が変わらない

`tests/determinism.test.ts` がこれを機械で見張っています。

## 層

上の層は下の層を呼べます。逆はいけません。

```
        main.ts            起動の順番だけ
           │
    ┌──────┴──────┐
   app            ui       ループ / 画面
    │              │
    ├──────┬───────┤
  render  save   audio     描画 / 保存 / 音
    │      │       │
    └──────┴───┬───┘
              sim          戦闘シミュレーション
               │
              data         マスタデータ
               │
              core         乱数・定数
```

`eslint.config.js` の `no-restricted-imports` が、
`sim` / `data` / `core` から上位層への import を機械で止めています。

### 逆向きが要るとき

シムが「決着した」ことを画面へ伝える必要があります。
これは **通知** で解いています（`src/sim/outcome.ts`）。

```ts
// sim 側：何が起きたかだけを言う
finishGame(true);

// ui 側：起動時に受け取り口を繋ぐ（main.ts）
onGameOver(endGame);
```

シムから画面を直接呼びたくなったら、まずこの形にできないか考えてください。

## モジュールの持ち場

### core/

| ファイル       | 持ち物                                                             |
| -------------- | ------------------------------------------------------------------ |
| `rng.ts`       | `mulberry32`。**実装を変えると過去のゴーストが全部無効になります** |
| `constants.ts` | `DT` `WORLD_W` `SPD_OPTS` `SAVE_KEY` など、値だけ                  |

### data/

| ファイル      | 持ち物                                                               |
| ------------- | -------------------------------------------------------------------- |
| `master.json` | 時代・系譜・バランス・ステージ・楽曲。**数値はすべてここ**           |
| `types.ts`    | master.json と 1:1 の型                                              |
| `master.ts`   | 展開して `ERAS` `LIN` `BAL` などへ配る。UI にも sim にも依存しない葉 |
| `skills.ts`   | 技の通し番号（`sai0` は原始の天災、`you3` は近世の妖）               |

`master.ts` は読み込まれた時点で `applyMaster(内蔵データ)` を済ませます。
だから他のモジュールは「`ERAS` が空かも」を気にしなくて済みます。

### sim/

| ファイル                               | 持ち物                                            |
| -------------------------------------- | ------------------------------------------------- |
| `state.ts`                             | `G`（一戦の全状態）。書き換えは `setG()` だけ     |
| `types.ts`                             | `Unit` `GameState` `Drawable` など                |
| `step.ts`                              | 1 フレームぶんの進行。ここがゲームの心臓          |
| `game.ts`                              | `newGame()`。**項目を足したらここに初期値を書く** |
| `unit.ts` `combat.ts` `affinity.ts`    | 兵の生成・被害・相性                              |
| `production.ts` `evolution.ts`         | 石高での生産・進化                                |
| `skills.ts` `disaster.ts` `summons.ts` | 時代技（天災と妖）                                |
| `outcome.ts`                           | 決着の確定と通知                                  |
| `fx.ts`                                | 演出の発生（`REPLAY` 中は何も作らない）           |

### render/

時代ごとに背景と前景をオフスクリーンへ**焼いて**使い回します（`caches.ts`）。
時代が変わったときと画面寸法が変わったときだけ捨てます。

`quality.ts` がフレーム間隔を見て、重ければ自動で細部を落とし、
それでも追いつかなければ描画解像度そのものを下げます（60fps 最優先）。

`viewport.ts` の `pushCamera` / `popCamera` は、
カードの絵姿や結果画面で同じ描画関数を流用するための視点差し替えです。

### save/

| ファイル    | 持ち物                                   |
| ----------- | ---------------------------------------- |
| `save.ts`   | 進行データ（勾玉・暦・素材・編成・強化） |
| `replay.ts` | 入力ログから一戦を再現する               |
| `ghost.ts`  | 自己ベストをゴーストとして並走させる     |

`REPLAY` が真のあいだ、演出・音・トースト・報酬付与はすべて止まります。

### ui/

画面ごとに 1 ファイル。DOM を触るのはここと `render/` だけです。
`bindings.ts` と `input.ts` が「どのボタンが何を呼ぶか」を持ち、
**モジュールを読んだだけでは何も起きません**（`initXxx()` を呼んで初めて繋がる）。

### platform/

`env.ts` の `IS_WEB` / `IS_DESKTOP` はビルド時に定数へ畳まれるので、
使わない側のコードはバンドルから丸ごと消えます。

疑似回転（縦持ちの端末を横画面に見せる）は Web 版だけの仕組みです。

## 起動の順番

`main.ts` にしか書いていません。順番には意味があります。

1. 設定（`initConfig`）── 以降の画面構築が `CFG` を読む
2. 進行データ（`loadSave`）── 編成が決まらないと盤面が作れない
3. 描画の下ごしらえ（`preparePalettes` → `initCanvas` → `resize`）
4. 画面の中身（設定・遊びかた・カード）
5. 結線（`initInput` など）── DOM が揃ってから listener を張る
6. 見せ盤面（`newGame(1)`）
7. ループ開始

`main.ts` にロジックを書かないでください。順番だけの場所です。
